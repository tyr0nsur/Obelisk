# FlowArk recovery into ObeliskNative

Source archive: `flowark-panel-and-ark-cluster-configs.zip`.
SHA256: `09d6cf020a57bed3369c89a4f9c7ef93b35c15bd93b745833f40be1394a4a21f`.
Recovered prefix: `flowark-panel/dashboard/`.

`RECOVERY_MANIFEST.json` records the 82 original recovered source files, their
original hashes and the exclusions. Subsequent implementation edits intentionally
differ from those recovery hashes. This is the existing private FlowArk code,
reused as the ObeliskNative dashboard base rather than replaced with another
independent panel.

The recovery excludes Git history, environment files, JWT material, runtime data,
admins/player records, databases, backups, logs, built assets, dependencies,
the separate Next.js marketing site, the Discord bot and all archived ArkApi
implementation code. Source was checked against the archive's actual secret
values and Discord webhook patterns; no recovered source replacements were
needed. Isolated test strings are fixtures, not production credentials.

No project LICENSE/NOTICE existed in the selected dashboard source. Source stays
private. Preserve third-party dependency notices in any distributed dashboard
artifact; recovering one's project does not remove dependencies' licenses.

Recovered stack: React 19/Vite 8/Tailwind 4 frontend, Express 5/Node backend,
RCON/GameDig, JSON state with per-file locking, atomic rename and fsync. Existing
routes cover users/roles, managed maps, LGSM lifecycle, console, moderation,
INI files, presets, scheduled tasks, audit and host health.

Historical deploy/orchestrator routes expose preflight and a planning wizard but
block installation/provisioning with 501. They do not yet implement a native
SteamCMD runner or managed shared-serverfiles lifecycle. Historical plugin UI
shows inventory and marker controls; the new Hub adds an explicit private socket
control contract. JSON state is designed for a single shared filesystem on one
host, not horizontally scaled control planes.

Recovery validation used Node 24 and locked npm installs without lifecycle
scripts. The recovered client built successfully. Tests revealed pre-existing
frontend markup guards and a CSP expectation mismatch; the historical README's
all-green claim is not accepted as current evidence. The Hub has its own focused
integration suite and the root integration pass records final combined results.

The original ARK installation, configs and saves were not changed by recovery.
No production panel or historical game service was automatically started.

The two historical one-off client source rewrite scripts (`apply_soft_theme.cjs`
and `update_health.cjs`) are omitted from the active tree after integration.
Their original hashes remain in the recovery manifest and their bytes remain
in the original ZIP. They must not overwrite the current views.
