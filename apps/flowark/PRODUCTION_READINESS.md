# FLOWARK Panel Production Readiness

Current production objective: make the dashboard safe to expose behind HTTPS for a small admin team without giving accidental host-level control beyond the intended ARK operations.

## Completed in this pass

- Server control commands now use `execFile` instead of shell interpolation.
- Server start/stop/restart responses now wait for the `SERVER_ACTION` audit entry to be persisted before returning success.
- `PORT`, `NODE_ENV`, and `CORS_ORIGINS` are configurable by environment.
- `HOST` defaults to `127.0.0.1`, aligning the Node process with the nginx reverse-proxy deployment and avoiding accidental direct exposure on all interfaces.
- Development login works without `secure` cookies while production keeps secure cookies.
- Discord webhooks are restricted to HTTPS Discord hosts and use native `fetch`.
- Discord webhook settings now require the exact `/api/webhooks/{id}/{token}` shape on `discord.com` or `discordapp.com` without query strings, fragments, or embedded credentials.
- `/api/server/logs` is defined once and tails configured map log files without shell interpolation.
- `/api/nodes` no longer depends on undefined `checkProcess` or simulated random stats.
- File manager paths are resolved with `realpath`, blocking symlink traversal outside managed roots, and malformed path/root parameters are rejected with stable Spanish JSON errors before filesystem access.
- File writes now accept empty files and enforce a 5 MB write limit.
- Scheduled tasks validate action, map, and broadcast payload.
- Frontend renders the `tasks` route, uses player `mapId` for player actions, and reloads settings when switching maps.
- Added explicit admin roles: `viewer`, `operator`, and `owner`.
- Legacy admins are migrated on startup: first legacy admin becomes `owner`, remaining legacy admins become `operator`.
- High-risk API routes now require `operator` or `owner` instead of any authenticated admin.
- Sensitive read-only operational routes for server logs, audit history, system health, and plugin runtime inventory now require at least `operator`; `viewer` can no longer inspect host diagnostics or admin activity.
- Desktop, mobile, and server sidebar navigation now hide privileged dashboard sections according to `viewer`/`operator`/`owner` role.
- Authenticated requests now revalidate the current admin record and role from storage, so deleted admins lose access immediately and role changes are reflected without waiting for JWT expiry.
- Dashboard admin deletion now rejects deleting the final `owner`.
- Owner-only dashboard admin updates now support username, role, and password changes, reject duplicate names and final-owner downgrade, and bump a per-admin session version.

## Remaining production blockers

- Replace role levels with scoped permissions if the admin team needs finer control than `viewer`/`operator`/`owner`.
- Rewrite git history and rotate any exposed `JWT_SECRET_KEY`, dashboard, Discord, RCON, or ARK credentials if this repository has already been pushed or backed up outside this host.
- Move JSON persistence for admins, audit, bans, players, and tasks to SQLite/Postgres before horizontal scaling or needing queryable relational history; current JSON locks are suitable only for a single shared filesystem on one host.
- Add plugin binary upload/install flows only after there is a signed artifact policy, staging directory, checksum validation, rollback plan, and explicit server restart workflow.
- Add an opt-in isolated integration environment for live ARK/RCON checks if production operators want end-to-end command validation beyond mocked route tests.
- Apply the deployment templates on the target host, verify nginx/systemd there, confirm the `ReadWritePaths=` entries match real runtime paths, and firewall the Node port so only 80/443 are exposed.
