# Tribe Scalar Boundary Design

## Scope

This note records the offline evidence boundary for a future internal tribe scalar checker.
It is not a public Tribe SDK claim, runtime observation, ABI contract, identity contract,
lookup contract, mutation contract, return-override contract, ResourceHandle contract, or
v1 completion signal.

## Evidence

- Binary hash in fixtures:
  `7e7ded49e0c658e74199801d79630bd33da407d3e468e039837bf61a9de7c520`.
- Fixture source:
  `tests/fixtures/ufunction_snapshots/7e7ded49e0c6/sdk_tribes/`.
- All cited snapshots are `candidate-only` offline-core observations generated by
  `scripts/inspect_core_ufunctions.py --snapshot-json`.

Accepted internal-only scalar/control candidates:

- `ShooterPlayerController.ServerRequestTribeLog`
  - `num_parms=0`, `parms_size=0`, empty property chain.
  - Use as zero-parameter control only; do not decode log strings or assert delivery.
- `ShooterPlayerController.IsInTribe`
  - `num_parms=1`, `parms_size=1`.
  - Only `ReturnValue` is present, `BoolProperty`, `offset_internal=0`,
    `bool_field_size=1`, `bool_byte_offset=0`, `byte_mask=0x1`, `field_mask=0xff`,
    `native_bool=false`.
- `ShooterPlayerController.AllowTribeGroupPermission`
  - `num_parms=3`, `parms_size=17`.
  - Scalar candidate: `TribeGroupPermission`, `ByteProperty`, `offset_internal=0`,
    `element_size=1`, enum candidate `ETribeGroupPermission`.
  - Redacted object candidate: `OnObject`, `ObjectProperty`, `offset_internal=8`,
    `element_size=8`.
  - Scalar return candidate: `ReturnValue`, `BoolProperty`, `offset_internal=16`,
    `bool_field_size=1`, `bool_byte_offset=0`, `byte_mask=0x1`, `field_mask=0xff`,
    `native_bool=false`.

Rejected/non-scalar candidates:

- `ShooterPlayerController.ClientReceiveMyTribeOnlineList`
  - `num_parms=1`, `parms_size=16`.
  - `OnlinePlayerIDs` is an `ArrayProperty` with `UInt32Property` inner candidate.
  - This must stay outside a scalar boundary because it is an online-list/player-id-like
    payload with identity/privacy implications.

## Checker Shape

A standalone `check_tribe_scalar_boundary_readiness.py` should stay offline and
candidate-only. It should report a ready internal scalar boundary only if:

- the three accepted targets above are present with exact names/outers and expected
  `num_parms`/`parms_size`;
- copied/internal scalar candidates are exactly:
  `IsInTribe.ReturnValue`,
  `AllowTribeGroupPermission.TribeGroupPermission`,
  `AllowTribeGroupPermission.ReturnValue`;
- `ServerRequestTribeLog` remains a no-param control;
- redacted/forbidden fields include `AllowTribeGroupPermission.OnObject`,
  online-list arrays, strings/log payloads, player/tribe identity, lookup, mutation,
  return override, public callbacks, runtime wiring, and `ResourceHandle`;
- all readiness flags for public SDK, public ABI/header, runtime, promotion, and v1
  completion remain false.

## Rejected Hypotheses

- `ClientReceiveMyTribeOnlineList` is not suitable for a scalar-only checker because it
  contains an array payload and online player IDs.
- `AllowTribeGroupPermission.OnObject` must not be copied as scalar evidence; it is an
  object reference and belongs to a future identity/lifetime/privacy review.
- The permission enum shape is not permission semantics. It can support an internal
  boundary check, but it does not prove authorization behavior, admin permissions,
  mutation authority, or public Tribe SDK readiness.
