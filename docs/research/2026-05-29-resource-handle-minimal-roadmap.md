# ResourceHandle Minimal Roadmap

## Objective

Define the smallest safe technical route toward an Obelisk `ResourceHandle` or public
resource identity surface without implementing it yet.

This note is design-only. It does not add a public ABI, does not promote `GObjects`, does
not expose raw `UObject`, and does not authorize runtime server access, marker changes,
ptrace, `gcore`, ReflectionScanner, native exec probes, mutation, or return overrides.

## Current Evidence Boundary

`minimal-second-source-intake` is now ready:

```text

gate_mode=second_source_promotion
promotion_gate.ready=true
blockers=[]
targets=4
second_source_accepted=4
```

That promotes only the selected sanitized UFunction layout comparison for:

- `PrimalItem.AllowRemoteAddToInventory`
- `PrimalItem.CanUse`
- `PrimalStructure.AllowStructureAccess`
- `PrimalStructure.IsAllowedToDemolish`

It does not promote `GUObjectArray`, `UObject` lifetime, `FUObjectItem` serial semantics,
object identity, public callbacks, mutation, or a resource lookup API.

The active identity blockers remain:

- `FUObjectArray` same-instance proof: the root/chunks/count evidence and serial-bearing
  accessor evidence are compatible, but still lack local/decompiler proof that
  `0x595b7e0`, `0x595b7f0`, `0x595b804`, and `0x595b838` are one `FUObjectArray`
  instance.
- Serial lifetime: static evidence favors `FUObjectItem+0x8` as the serial-backed dword;
  `FUObjectItem+0xc` remains unknown, and current copied-core samples show `+0x8 == 0`.
- `uobject_flags_validity_semantics_unproven`: `UObject+0x8` is confirmed as a 32-bit
  object flags field for the current binary hash. Static weak-handle/object-validity
  helpers consult `0x100` and `0x4000` after `{index, serial}` validation, but accepted
  copied-core samples only show plausible live objects with flags such as `0x81`, `0xc7`,
  and `0xc5`. No sample proves rejection because either mask is set, and no
  version-matched UE4 lifetime name or destroyed/pending-kill/unreachable semantic is
  accepted.
- Object class/outer redaction: class and outer are useful for internal validation and
  classification, but they can disclose game identity and must not be public payload.
- No raw `UObject`: plugins must never receive UE pointers, object-array coordinates,
  `InternalIndex`, FName/GObjects indices, `FUObjectItem` addresses, or UE serials.

## Minimal Public Shape

The first safe public shape, if the missing evidence is later accepted, should be narrower
than a general object API:

```text
opaque process-local ResourceHandle
category/resource_kind only by default
no public resolve-to-UObject
no mutation or return override
no cross-instance, cross-map, cross-restart, or cluster persistence
no raw class, outer, name, index, serial, pointer, or address-derived value
```

The handle value must be generated by Obelisk and backed by an internal table. It must not
encode `GObjects` index, serial, pointer bits, FName index, class, outer, or artifact
identity. Public use should start as correlation-only for an approved resource kind, not
as lookup or mutation.

## Promotion Ladder

### 0. Current State: Category Only

Keep `GameplayPolicyEvent.resource_kind` as category-only metadata. It is suitable for
routing, metrics, and sanitized logs. It is not identity and must not be treated as "same
structure", "same inventory", or "same actor".

Promotion status: already public as category metadata through `DescribeResourceKind`.

### 1. Internal `ResourceIdentityCandidate`

Allow only internal event builders to construct a non-public candidate from a caller or
reflected object parameter.

Required checks:

- exact reflected target and `ParmsSize` already accepted for the event surface;
- pointer is readable and plausible as `UObject`;
- `UObject.InternalIndex` is non-negative and in current `GObjects` count;
- `GObjects[InternalIndex].Object == pointer`;
- class pointer and outer pointer are null or also pass direct object-array membership;
- resource kind is assigned by an allowlisted reflected target/class policy;
- class, outer, object name, pointer, index, serial, and FName data are dropped before any
  plugin callback.

Promotion criteria:

- same-instance `FUObjectArray` evidence is accepted for the binary hash;
- a second-source GObjects/UObject sample pack repeats direct target/class/outer
  membership with complete artifact identity;
- negative fixtures reject index mismatch, missing chunk, unreadable object, class
  non-membership, outer non-membership, and missing artifact-specific FName root;
- no public ABI or SDK surface exists yet.

### 2. Hook-Frame Internal Handle

Introduce only an internal callback-frame handle if needed for dispatcher dedupe or
redaction bookkeeping. The handle expires before returning from the Obelisk-owned
dispatch path and cannot be stored by plugins because it is not public.

Promotion criteria:

- internal table tests prove generation reuse cannot alias within a frame;
- cleanup tests clear all frame handles on normal return, early return, recognizer reject,
  plugin callback failure, and owner cleanup;
- revalidation fails closed when object-array membership changes or serial evidence is
  absent.

### 3. Public Process-Local Correlation Handle

Expose a public `ResourceHandle` only after serial and lifetime evidence can support
post-callback revalidation. Initial scope should be one low-risk resource kind, preferably
structure-backed policy events, because the existing public surface already has copied POD
payloads and redaction policy.

Promotion criteria:

- `FUObjectItem+0x8` semantics are accepted as the stale-handle serial field, or a
  different exact field is proven and the `+0xc` hypothesis is explicitly rejected or
  explained;
- zero serial behavior is understood well enough to reject handles without serial
  publication or to constrain them to hook-frame only;
- slot reuse changes the accepted serial or otherwise fails revalidation;
- `uobject_flags_validity_semantics_unproven` is closed with negative samples or an
  independent source/decompiler path proving the exact `UObject+0x8` reject bits and
  lifetime semantics;
- table lookup revalidates `{internal index, accepted serial, object pointer, kind}` before
  returning any public result;
- public result remains copied POD metadata only and never exposes raw UE internals.

Public semantics:

- valid only in the current process;
- invalid after restart, map change, module unload, or failed revalidation;
- capability-gated;
- no conversion to pointers, indices, names, locations, inventory, tribe/player identity,
  or mutation operations.

### 4. Explicitly Out Of Scope

Do not design these until separate evidence and policy exist:

- persistent IDs across restarts or cluster travel;
- player, tribe, inventory, dino, transfer, or uploaded-object identity;
- class/outer/name descriptors exposed to plugins;
- object lookup APIs that return raw or borrowed UE storage;
- mutation, command, teleport, ownership, pin code, inventory transfer, or return-override
  APIs.

## Tests Needed

Offline Python/tooling tests:

- static same-instance proof fixtures for root/chunks/count/serial windows, including
  near-miss cases that keep `missing_gobjects_coherent_field_window`;
- GObjects reconciliation fixtures that require target, class, and outer
  `GObjects[InternalIndex]` backrefs;
- protected path rejection for every identity intake input and output;
- readiness/report tests that reject missing or partial artifact identity, self-comparison,
  reused primary FName roots, and `scan-only` results as promotion evidence;
- serial fixtures covering `item+0x8` zero, nonzero, mismatch, missing item, and `+0xc`
  non-promotion.

C++ internal tests:

- candidate builder rejects null, unreadable, out-of-bounds, index mismatch, class
  non-member, outer non-member, unsupported target, and unsupported resource kind;
- internal handle table generation cannot alias after reuse;
- cleanup clears handles on dispatcher exit, callback unregister, init failure, and
  plugin unload;
- stale or missing serial evidence prevents public handle creation.

Public ABI and SDK tests, only when a public handle is proposed:

- append-only C ABI layout and capability-bit tests;
- installed SDK consumer tests for feature detection, register/unregister, handle
  comparison, failed lookup, and shutdown cleanup;
- guardrail tests proving public headers/docs do not expose `UObject`, `UFunction`,
  `FString`, raw params, FName/GObjects indices, `InternalIndex`, `FUObjectItem`, class,
  outer, or pointer-derived IDs;
- redaction tests for logs, JSON reports, snapshots, and event payloads.

## Evidence Still Missing

- A promotion-grade same-instance proof for the `FUObjectArray` candidate: either a
  coherent local executable window or decompiler/static evidence tying root, chunks,
  count, and serial to the same instance.
- A distinct second-source GObjects/UObject promotion report, not just UFunction snapshot
  readiness, with artifact-specific FName root and direct target/class/outer membership.
- Nonzero serial evidence or static decompiler evidence sufficient to prove
  `FUObjectItem+0x8` invalidation behavior, zero handling, and slot reuse.
- Closure for `uobject_flags_validity_semantics_unproven`: a mapping for the
  `UObject+0x8` masks used by the handle accessor path, including negative samples or an
  independent source/decompiler path for the exact reject semantics.
- A written redaction and capability policy for public event correlation.
- ABI, lifecycle, installed SDK consumer, and release-doc guardrails for any public handle.

## Minimal Next Step

Do not implement `ResourceHandle` yet. The next useful step is evidence-only:

1. Close or formally refine the same-instance static blocker for `0x595b7e0` using the
   narrow decompiler/static plan already scoped around `0x1d4a8b0..0x1d4aa18`,
   `0x1d56970..0x1d56a26`, and `0x1d56d60..0x1d56ecd`.
2. Produce a second-source GObjects/UObject reconciliation report with explicit
   artifact-specific FName root, no protected paths, complete artifact identity, and
   direct target/class/outer membership.
3. Keep any handle design internal and hook-frame-only until serial lifetime/reuse and
   `uobject_flags_validity_semantics_unproven` are resolved; do not promote public
   identity, post-callback lookup, mutation, or return overrides.
